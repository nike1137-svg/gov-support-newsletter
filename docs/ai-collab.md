# AI 협업 기록

이 프로젝트는 2026-09-15 하루 동안 **Claude Code** 와 대화하며 만들었다.
누가 무엇을 정했고, 어떤 요청을 했고, 어디서 틀렸는지를 남긴다. 기술적 결함과 고친 방법은 [dev-log.md](dev-log.md) 에 있다.

## 일하는 방식 (미리 정해 둔 규칙)

AI 코딩 에이전트 공용 규칙 파일(`~/.claude/CLAUDE.md`)에 적어 두고 시작했다. 이 프로젝트에 영향을 준 것만:

| 규칙 | 이 프로젝트에서 드러난 모습 |
|---|---|
| 단계별 승인 — 작업 전에 목적 · 현재 상태 · 결과를 설명하고 승인받기 | 소스 기준 · 분야 · 채널 · 공개 여부를 매번 승인받고 진행. 중간에 "단계가 끝나면 알려주는 형식"으로 바꿈 |
| 새 서비스·API 를 쓰기 전에 무료 한도 · 자동 과금 확인 | 기업마당 · K-Startup · OpenAI 가격 · 텔레그램 · Actions 를 붙이기 전에 조사해 보고 |
| API 키는 `.env` 에만, 채팅에 붙여 넣지 않기 | 키 4종 모두 메모장으로 직접 입력. AI 는 값을 출력하지 않고 길이 · 형식 · 호출 결과만 확인 |
| 오류가 나면 만든 파일을 지우고 확인한 뒤 재작업 | 실패한 실행의 기록 파일을 매번 지우고 다시 돌림 |
| 다중 원인 검토 (데이터 · 설계 · 실행 · 검증) | 결과가 이상할 때 LLM 보다 측정 도구 · 대조 함수를 먼저 의심 |

프로젝트 전용 규칙은 [CLAUDE.md](../CLAUDE.md).

| 채택 1곳뿐일 때 **"독자에게 필요한 정보로 범위를 넓히면 RSS 가 더 있다"** | RSS 후보 19곳 탐색 · 기준 v2 초안 · 13곳 측정 |
| **"채택·탈락 이유와 기준 검증을 놓치면 안 된다"** — 측정보다 기준 먼저 | 기준 C1~C5 문서 · 측정 스크립트 · 결과표 |
| 측정 순서: **키를 받은 뒤 4곳을 같은 시각에** | K-Startup swagger 에서 호출 주소 · 파라미터 확인 |
| 기업마당 가입 · 키 발급, K-Startup · OpenAI · 텔레그램 키 입력 | 키가 동작하는지 값 노출 없이 확인 |
| **루브릭 제시** — "이게 우리 평가기준이야" | 루브릭 항목마다 필요한 증거(라벨 · 검수 증명)를 설계에 반영 |
| **제출물 구조는 예시대로**, 개별 파일은 추가 | `audience.yaml` 로 기준 분리 · 폴더 구조 |
| 중요도 기준 초안 승인 · 발행 채널 텔레그램 · 공개 저장소 · 매일 07:30 | `graph.py` 노드 6개 · `run.py` · 워크플로 |
| 이름 **"1인 창업 지원 뉴스 브리핑 에이전트"** | 쓰는 곳별로(보고서 / 메시지 머리말) 나누자고 제안 |
| **"내 깃허브를 클론해서 다른 사용자가 쓸 수 있는지 확인해봐"** | 새 클론 점검 → 키 없을 때 가짜 "정상" 발견 · 수정 |
| 노션 페이지 형식 · README 최신화 · 피어리뷰 템플릿 점검 | 노션용 변환 · README 점검표 · PRT 자가 점검 |

## AI 가 틀렸고 마커스님이 잡은 것

| 상황 | AI 가 한 것 | 마커스님의 한마디 | 바뀐 것 |
|---|---|---|---|
| 과제 확인 | 메모리에 요약해 둔 문장을 **"과제 원문"이라고 인용**하고, 과제에 없는 실험 · 확인 안 된 비용까지 붙임 | "어텐션 할루시네이션 중지 재 답변" | 근거가 있는 것과 없는 것을 나눠 다시 답함. 이후 "원문을 달라"고 요청하는 쪽으로 |
| 새 저장소 여부 | 질문 방향에 맞춰 판단을 **두 번 뒤집음** | "그럼 기존에 만든것을 그대로 사용하자는 말이야? 그게 맞는것 같아?" | 새 근거 없이 바꿨음을 인정하고 근거로만 재판단 |
| 소스 검증 | **기준을 정하지 않고 측정부터** 함 | "특정 소스를 채택하거나 탈락시킨 이유와 기준을 명확히 검증합니다. 이런 부분들 놓치면 안되는거야" | 기준 확정 → 측정 → 결과표 순서로 |
| 작업 위치 | 새 폴더를 만들고도 **세션은 이전 프로젝트 폴더**에서, 그 프로젝트의 가상환경으로 실행 | "지금 폴더 변경 안된 상태야 폴더 변경하고 진행해야하는거 아니야?" | 폴더 이동 · 전용 가상환경 |
| 범위 판단 | 채택 1곳에서 원천 기관만 더 찾으려 함 | "좀 더 범위를 넓혀서… 좀 더 깊이 있게 사고해보자" | 구조(허브와 원천) · 기준 설계 자체를 다시 봄 |

## AI 가 스스로 잡은 결함 (요약)

전부 [dev-log.md](dev-log.md) 에 원인과 재발 방지 검증이 있다.

- 선별: LLM 이 '중소기업' 공고 9건을 대기업 전용으로 버림 · **본선 번호가 한 칸 밀려 다른 기사의 이유가 붙음**
- 요약: **'상시근로자 5인 이상' 공고에 1인 창조기업이 참여하라는 인사이트** (실제로 한 번 발행됨) · 추측으로 대상아님 판정
- 검수: 증명 첫 결과 **3/8** — AI 가 만든 인용 대조가 너무 엄격했음
- 측정: K-Startup 정렬 · 필터 · 전체 건수를 잘못 믿어 결과가 두 번 무효
- 발행: `requirements.txt` 에 `trafilatura` 누락으로 Actions 첫 실행 실패
- 제출 후: 키 없이 실행하면 "정상 실행됐습니다" · 수집 검증이 '0/0' 으로 통과. 이를 시험하다 **PowerShell 빈 값 대입이 변수를 지운다는 걸 몰라 실제 LLM 실행을 한 번 돌림**

## 실제로 한 요청 (프롬프트) 예시

긴 설계 문서 대신 짧은 요청과 이미지(과제 · 루브릭 · 템플릿 캡처)로 진행했다. 방향을 바꾼 요청들:

| 시점 | 요청 (원문) | 결과 |
|---|---|---|
| 착수 | 과제 이미지 첨부 + "이부분부터 다시 진행하자." | 필수 5단계 대비 현재 위치 점검 |
| 분야 | "좀더 범위를 넓혀서 진행하는게 맞는것 같은데 지금 4곳에서 1곳인데 실제 api를 제공하는곳도 한정적일수 있고 좀더 깊이 있게 사고해보자" | 데이터 · 설계 · 실행 · 검증 레이어로 재검토 |
| 범위 | "혼자 사업을 준비하거나 막 시작한 1인 창조기업 운영자에게 필요한 정보를 제공하는것으로 범위를 늘리면 좀더 많은 rss가 제공 될수 있잖아" | 기준 v2 · 채택 4곳 |
| 진행 방식 | "지금부터 단계가 끝나면 나에게 알려주는 형식을 취하자 진행해" | 단계 안에서는 진행, 끝나면 보고 |
| 평가 | 루브릭 이미지 + "이게 우리 루브릭의 평가기준이야" | 선별 라벨 기록 · 검수 증명 · 대체 경로 설계 |
| 의도 확인 | (설치 명령을 거부한 뒤) "내 의도를 너가 정확히 이해했는지를 알려고 거부 한거야" | AI 가 이해한 내용을 먼저 말하고 진행 |
| 사용자 관점 | "지금 내 깃허브 클로해서 다른 사용자가 사용할수 있는지 확인해봐" | 키 누락 가드 · `tools/verify_env.py` |

## 돌아보며

- **AI 가 만든 결과도 코드로 대조해야 했던 것처럼, AI 의 말도 확인해야 했다.** "원문", "정상 실행", "4/4 통과"가 틀린 적이 있었다. 근거 파일을 보자고 하거나 직접 클론해 보게 한 요청이 그걸 드러냈다
- **짧은 지시라도 기준을 먼저 주면 결과가 달라졌다.** 과제 이미지 · 루브릭 · 제출물 구조를 보여준 뒤부터 설계가 평가 기준을 향했다
- AI 는 구현과 측정이 빠르지만 **"무엇을 기준으로 삼을지"는 사람이 정할 때 흔들리지 않았다**
